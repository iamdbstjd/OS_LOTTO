1. 프로젝트 개요

본 보고서는 Django와 Docker를 활용하여 개발한 Lotto 사이트의 설계, 구현 과정, 주요 화면 및 테스트 결과를 정리한 문서이다. 본 시스템은 6/45 로또 서비스를 웹 환경으로 구현한 과제용 프로젝트로, 사용자와 관리자 두 가지 역할을 지원한다.

일반 사용자는 회원가입 및 로그인 이후 수동 또는 자동 방식으로 로또를 구매할 수 있으며, 구매한 티켓은 사용자별로 데이터베이스에 저장된다. 추첨이 완료된 회차에 대해서는 당첨 여부와 당첨금을 확인할 수 있다.

관리자는 전체 판매 현황 및 판매 내역 조회, 추첨 기능 실행, 회차별 당첨자 수 및 서비스 이익 확인 등의 운영 기능을 수행할 수 있다.

구현 과정에서 GPT를 보조 도구로 활용하였으며 소스 코드는 위 GitHub 저장소에 공개되어 있다.

2. 주요 요구사항 반영

2.1 사용자 기능

본 프로젝트에서 구현한 사용자 기능은 회원가입 및 로그인, 사용자별 구매 기록 저장, 수동 구매, 자동 구매, 구매 내역 조회, 당첨 확인으로 구성된다.

수동 구매는 사용자가 1부터 45 사이의 번호 6개를 직접 입력하여 구매하는 방식이다. 자동 구매는 시스템이 1부터 45 사이에서 중복 없는 번호 6개를 자동 생성하여 구매하는 방식이다. 각 구매 건에는 L0001-000001 형식의 고유 티켓번호가 자동으로 발급되며, 사용자는 본인의 전체 구매 장수, 총 구매액, 총 당첨금, 추첨 대기 건수를 확인할 수 있다.

구매 내역 화면에서는 로그인한 사용자 본인의 티켓만 조회할 수 있으며, 당첨 확인 화면에서는 추첨 완료 회차의 일치 개수, 보너스 번호 일치 여부, 등수, 당첨금을 확인할 수 있다.

2.2 관리자 기능

관리자는 전체 판매 장수, 총 판매액, 총 지급액, 서비스 이익을 확인할 수 있다. 또한 현재 판매중인 회차에 대해 추첨을 실행할 수 있으며, 추첨이 완료되면 회차별 판매 장수, 판매액, 지급액, 이익을 조회할 수 있다.

판매 내역 화면에서는 최근 발급된 티켓의 사용자, 티켓번호, 구매 번호, 결과를 확인할 수 있다. 당첨 상세 화면에서는 회차별 1등부터 5등까지의 당첨 인원과 구매자별 당첨 내역을 확인할 수 있다.

2.3 Docker 요구사항

서비스는 Docker multi-container 구조로 구성하였다. web 컨테이너는 Django 애플리케이션을 실행하고, db 컨테이너는 PostgreSQL 데이터베이스를 실행한다. postgres_data Docker volume은 데이터베이스 데이터를 영속적으로 보존하기 위해 사용된다.

3. 시스템 설계

3.1 시스템 아키텍처

본 시스템은 브라우저, Django 애플리케이션 컨테이너, PostgreSQL 데이터베이스 컨테이너의 3계층 구조로 구성된다.

Browser -> web container (Django: views / forms / services / templates) -> db container (PostgreSQL)

Django 애플리케이션은 화면 출력, 로그인 세션 관리, 구매 처리, 추첨 처리, 당첨 계산을 담당한다. PostgreSQL 컨테이너는 사용자, 회차, 티켓, 당첨 결과 데이터를 저장한다.

로컬 테스트 편의를 위해 환경 변수 DB_HOST가 설정되지 않은 경우 SQLite를 사용하며, Docker Compose 실행 시에는 DB_HOST=db로 설정되어 PostgreSQL이 활성화된다.

3.2 데이터 모델

3.2.1 Draw

Draw 모델은 로또의 각 회차를 나타내며, 다음 필드로 구성된다.

필드명 설명
round_number 회차 번호
status 현재 상태 (판매중 / 추첨완료)
winning_numbers 당첨 번호 6개
bonus_number 보너스 번호
drawn_at 추첨 일시

3.2.2 Ticket

Ticket 모델은 사용자가 구매한 로또 티켓을 나타내며, 다음 필드로 구성된다.

필드명 설명
user 티켓을 구매한 사용자
draw 해당 구매가 속한 회차
ticket_code 고유 티켓번호 (예: L0001-000001)
numbers 구매 번호 6개
purchase_type 구매 방식 (수동 / 자동)
price 구매 금액
match_count 당첨 번호와 일치한 개수
matched_bonus 보너스 번호 일치 여부
prize_rank 당첨 등수
prize_amount 당첨금

3.3 당첨 판정 기준

실제 로또 규칙을 기준으로 등수를 산정하며, 판정 기준은 아래 표와 같다.

등수 당첨 조건 당첨금
1등 당첨 번호 6개 모두 일치 2,000,000,000원
2등 당첨 번호 5개 + 보너스 번호 일치 50,000,000원
3등 당첨 번호 5개 일치 1,500,000원
4등 당첨 번호 4개 일치 50,000원
5등 당첨 번호 3개 일치 5,000원

당첨금은 과제 시연 및 이익 계산의 단순화를 위해 고정 금액으로 설정하였다. 서비스 이익은 다음 공식에 따라 계산한다.

서비스 이익 = 총 판매액 - 총 지급액

4. 화면 및 기능 설명

아래 설명은 제출 보고서 목적으로 데모 데이터를 기반으로 작성하였다.

4.1 로그인 화면

로그인 화면에서는 기존 사용자가 아이디와 비밀번호를 입력하여 서비스에 접속한다. 로그인 버튼을 클릭하면 Django 인증 시스템으로 입력 계정 정보를 검증한다. 인증에 성공하면 로또 구매 메인 화면으로 이동하고, 인증에 실패하면 로그인 화면에 오류 메시지가 표시된다. 회원가입 링크를 클릭하면 신규 사용자 등록 화면으로 이동한다.

4.2 회원가입 화면

회원가입 화면에서는 신규 사용자가 아이디, 이메일, 비밀번호를 입력한다. 가입하기 버튼을 클릭하면 Django UserCreationForm 기반으로 사용자 계정이 생성된다. 가입에 성공하면 자동 로그인 처리 후 구매 메인 화면으로 이동하며, 비밀번호 조건을 충족하지 못하거나 중복 아이디를 입력하면 폼 오류 메시지가 표시된다.

4.3 사용자 메인 및 구매 화면

사용자 메인 화면은 현재 판매중인 회차 정보, 사용자 구매 요약, 수동 구매 영역, 자동 구매 영역, 최근 구매 내역을 제공한다. 상단 구매하기 버튼을 클릭하면 화면 하단의 구매 영역으로 이동하고, 당첨 확인 버튼을 클릭하면 당첨 확인 페이지로 이동한다.

수동 구매 영역에서는 사용자가 1번부터 6번까지의 입력 칸에 번호를 직접 입력한다. 중복 번호 또는 범위 외 번호를 입력하면 서버 측 검증을 통해 오류가 표시된다. 자동 구매 영역에서는 구매 수량을 입력한 후 자동 구매 버튼을 클릭하면 시스템이 번호를 자동 생성하여 티켓을 발급한다. 최근 구매 영역에서는 티켓번호, 구매 방식, 번호, 추첨 전/당첨/낙첨 상태를 확인할 수 있다.

4.4 사용자 구매 내역 화면

구매 내역 화면은 로그인한 사용자 본인의 티켓 정보만 표시한다. 사용자는 티켓번호를 통해 각 구매 건을 식별할 수 있으며, 구매 방식이 수동인지 자동인지 확인할 수 있다. 구매 번호는 로또 볼 형태로 시각화되며, 추첨 전/낙첨/1등부터 5등까지의 결과와 당첨금이 함께 표시된다.

4.5 사용자 당첨 확인 화면

당첨 확인 화면은 추첨이 완료된 회차의 티켓만 표시한다. 일치 항목에서는 당첨 번호와 사용자 구매 번호가 몇 개 일치했는지 확인할 수 있고, 보너스 항목에서는 보너스 번호 일치 여부를 확인할 수 있다. 결과 항목에는 로또 등수 또는 낙첨 여부가 표시되며, 당첨금 항목에는 등수별 고정 당첨금이 표시된다.

4.6 관리자 대시보드 화면

관리자 대시보드는 전체 판매 현황 조회와 추첨 실행 기능을 제공한다. 추첨 버튼을 클릭하면 현재 판매중인 회차의 당첨 번호 6개와 보너스 번호가 생성되고, 해당 회차의 모든 티켓이 평가된다. 평가 과정에서 일치 개수, 보너스 일치 여부, 당첨 등수, 당첨금이 저장되며, 추첨 완료 후 다음 회차가 자동으로 생성된다.

판매 내역 보기 버튼을 클릭하면 관리자 판매 내역 화면으로 이동한다. 관리자는 전체 판매 장수, 총 판매액, 총 지급액, 서비스 이익을 확인할 수 있으며, 추첨 내역 표의 상세 링크를 클릭하면 해당 회차의 당첨 상세 화면으로 이동한다.

4.7 관리자 판매 내역 화면

판매 내역 화면은 관리자 전용 화면으로, 회차별 판매 요약과 최근 발급 티켓 목록을 제공한다. 회차별 판매 요약에서는 회차 상태, 판매 장수, 판매액, 지급액, 이익을 확인할 수 있으며, 추첨 완료 회차의 당첨 상세 링크를 통해 상세 결과 화면으로 이동할 수 있다.

최근 발급 티켓 영역에서는 구매 일시, 티켓번호, 사용자, 회차, 구매 방식, 번호, 결과, 당첨금을 티켓 단위로 표시한다. 이를 통해 관리자는 실제 판매 내역을 사용자와 회차 기준으로 추적할 수 있다.

4.8 관리자 당첨 상세 화면

관리자 당첨 상세 화면은 특정 회차의 추첨 결과 및 구매자별 결과를 상세히 보여준다. 당첨 번호 영역에는 해당 회차의 당첨 번호 6개와 보너스 번호가 표시된다. 판매액 및 이익 영역에서는 해당 회차의 전체 판매 금액과 판매액 - 지급액으로 계산된 이익을 확인할 수 있다.

등수별 요약 영역에서는 1등부터 5등까지의 당첨자 수와 등수별 당첨금을 표시한다. 구매자별 결과 영역에서는 사용자, 티켓번호, 구매 번호, 일치 개수, 보너스 일치 여부, 결과, 당첨금을 상세히 확인할 수 있다.

5. 구현 과정

1단계에서는 Django 프로젝트 lotto_project와 앱 lotto를 생성하고, 사용자 화면 및 관리자 화면을 위한 URL, View, Form, Template의 기본 구조를 설계하였다.

2단계에서는 Django 기본 인증 시스템을 활용하여 회원가입, 로그인, 로그아웃 기능을 구현하였다. 구매, 구매 내역, 당첨 확인 페이지는 로그인한 사용자만 접근 가능하도록 제한하였으며, 관리자 기능은 is_staff 권한을 보유한 사용자에게만 허용하였다.

3단계에서는 구매 기능을 구현하였다. 수동 구매는 ManualTicketForm을 통해 6개 번호를 입력받고, 중복 여부 및 1~45 범위를 서버 측에서 검증한다. 자동 구매는 Python의 random.sample 함수를 사용하여 중복 없는 번호 6개를 자동 생성한다. 티켓 저장 시에는 L0001-000001 형식의 고유 티켓번호를 자동 발급하여 사용자와 관리자가 동일한 구매 건을 명확하게 식별할 수 있도록 하였다.

4단계에서는 추첨 및 당첨 계산 기능을 구현하였다. 관리자가 추첨 버튼을 실행하면 현재 판매중인 회차의 당첨 번호 6개와 보너스 번호가 생성된다. 이후 해당 회차의 모든 티켓을 순회하며 일치 개수, 보너스 일치 여부, 등수, 당첨금을 산정하여 저장한다. 추첨 완료 후에는 다음 회차가 자동으로 생성된다.

5단계에서는 사용자 및 관리자 통계를 고도화하였다. 사용자 화면에는 본인의 전체 구매 장수, 총 구매 금액, 총 당첨 금액, 추첨 대기 건수를 제공하였다. 관리자 화면에는 전체 요약 외에도 회차별 판매 요약과 최근 발급 티켓 목록을 제공하여 판매 내역 확인 요구사항을 충족하도록 하였다.

6단계에서는 Docker multi-container 환경을 구성하였다. docker-compose.yml 파일에 Django web 서비스와 PostgreSQL db 서비스를 정의하였고, db 서비스에는 healthcheck를 추가하여 데이터베이스 준비가 완료된 후 Django 마이그레이션 및 서버 실행이 진행되도록 구성하였다.

6. 실행 방법

Docker 환경에서 아래 명령어를 실행하여 서비스를 시작한다.

docker compose up --build

서비스 시작 후 웹 브라우저에서 아래 주소로 접속한다.

http://localhost:8000

관리자 기능을 사용하려면 아래 명령어로 관리자 계정을 별도로 생성해야 한다.

docker compose exec web python manage.py createsuperuser

7. 테스트 결과
